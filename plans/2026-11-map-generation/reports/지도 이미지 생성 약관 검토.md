# 원클릭 대형 지도, 브이월드 승낙으로 연다

> 조사일 2026-11-25. 근거는 같은 폴더의 `research_notes/지도 이미지 생성 약관 검토/` 5개 노트(카카오·네이버·구글·공공데이터·기술/해외 상용). 법률 자문이 아니다. 확인하지 못한 내용은 `확인 필요`로 표시했다.

조사한 어느 사업자도 **"서비스가 지도 이미지를 만들어 파일로 내려주는 것"을 사전 동의 없이 허용하지 않는다.** 카카오는 "실시간 호출만 가능"·"사전 승낙 없는 복제 금지", 네이버는 "결과 데이터는 받은 즉시 1회만 사용·무단 저장·가공 금지", 구글은 "서비스 밖 사용을 위한 export·store·타일 대량 다운로드 금지"를 둔다. 그래서 2024-09 서버 타일 합성을 접은 판단은 옳았고, 지금의 '공식 SDK로 큰 지도 한 장 → 사용자가 직접 캡처' 구조는 각 사업자가 허용 쪽으로 답한 유일한 행위(**사용자 개인의 화면 캡처·브라우저 인쇄, 로고·저작권 표시 유지**)에 기대는 가장 방어적인 형태다. 이 구조를 지키면서 '버튼 한 번'으로 가는 길은 둘이다. 첫째, **브이월드**는 약관이 영리 이용을 사전 승낙 없이 허용하고 "캡처화면"의 출처 표기까지 규정하며, 타일 서버가 CORS를 열어 두어 브라우저에서 바로 합성할 수 있다. 다만 "무단 저장"·"사전 승낙 없는 복제·타인 제공" 금지 조항이 있어 **운영기관의 서면 승낙**이 열쇠다(비용 0원). 둘째, 카카오·네이버 지도는 **브라우저 기본 인쇄(PDF 저장)를 버튼으로 호출**하는 방식이 카카오 답변상 허용 범위에 가장 가깝다. 추천 순서는 ① 브이월드·카카오·네이버 서면 문의(즉시, 비용 0) ② 브이월드 위성/배경의 브라우저 합성 원클릭 다운로드(승낙 후 공개) ③ 카카오·네이버용 '인쇄/PDF' 버튼 ④ 카카오 답변이 긍정적일 때만 getDisplayMedia 탭 캡처 합성이다. 정적 지도 이어 붙이기, Google Map Tiles 합성, 서버 헤드리스 렌더링, 해외 유료 API는 약관이나 비용(무료 한도) 때문에 배제한다.

## 다섯 사업자 모두 '저장'을 막고, 다른 것은 예외 문구뿐이다

약관 문언을 나란히 놓으면 사업자 간 차이는 "무엇을 금지하나"가 아니라 "**어디에 예외를 열어 두었나**"에 있다. 아래 표는 맵샷이 따지는 여섯 가지 쟁점별로 원문 근거를 모은 것이다.

### 카카오: 약관은 침묵하고, 게시판 답변이 경계를 긋는다

Kakao Developers 운영정책(2026-04-20 시행)에는 지도 이미지·캡처·인쇄를 직접 다루는 조항이 없다. 실제 경계는 DevTalk의 카카오맵 API 운영 측 답변이 만든다. 단일 지도 화면을 자동 캡처해 사용자 기기에 보관하는 것은 **"개인 사용자의 화면 캡처와 같은 범위로 보아 사용하셔도 됩니다"**라고 하면서 "저장된 이미지에서도 카카오 로고와 저작권 표시는 유지"하라고 했다 ([DevTalk 152313](https://devtalk.kakao.com/t/topic/152313)). 로드뷰 페이지의 PDF 인쇄도 "사용자 브라우저의 기본 기능을 통한 개인 목적의 PDF 출력은 데이터 별도 저장에 해당하지 않아 사용 가능"하다고 답했다 ([DevTalk 151107](https://devtalk.kakao.com/t/pdf/151107)). 반대로 Selenium으로 로드뷰를 수백 장 자동 캡처하는 것은 **"정책 상 허용하지 않으며"** 실시간 호출로만 쓰라고 했다 ([DevTalk 151931](https://devtalk.kakao.com/t/ai/151931)). html2canvas로 지도를 PDF에 넣으려던 개발자에게는 "스크린샷으로 지도를 캡처해주세요"라고 권했다 ([DevTalk 127514](https://devtalk.kakao.com/t/pdf-html2canvas/127514)). 공공기관 홍보영상에 캡처를 쓰는 질문에는 "kakao 로고가 삽입된 화면을 캡쳐하여 사용"하라고 해, 로고를 남기는 조건으로 2차 결과물 사용을 용인했다 ([DevTalk 136914](https://devtalk.kakao.com/t/topic/136914)). 영리 부동산 서비스의 스카이뷰 사용도 "활용 가능"하고 출처 표기 의무는 없다고 답했지만, 이는 SDK 실시간 렌더링 맥락이다 ([DevTalk 151446](https://devtalk.kakao.com/t/skyview/151446)). 답변자 표시명만으로는 직원 신분이 드러나지 않고 개별 문의에 대한 답이라 일반 규정으로 단정할 수 없다(공식성 확인 필요). 남은 회색지대는 **캡처본을 도면·보고서에 넣어 발주처에 내는 행위가 "개인 캡처"인지 "문서를 생성하여 배포"(151107의 제외 사례)인지**, 그리고 **5000px급 단일 지도도 개인 캡처 범위로 보는지**다. 둘 다 답변이 없다.

### 네이버: 문언이 가장 넓고, 정식 탈출구는 "사전 동의"다

NCP Maps 약관(v0.4, 2025-03-20 시행, 최신판 여부 확인 필요)은 캡처·인쇄를 언급하지 않지만, 결과 데이터를 "본 약관에서 허용한 범위를 넘어서서 무단으로 복제, 저장, 가공, 배포"하지 못하게 하고(제7조 ⑨) **"값을 리턴 받는 즉시 1회 자신의 서비스에서 사용하는 것만 허용"**한다(제7조 ⑪). 회사는 "산출물 등 결과물 및 외부 송출 내역을 모니터링"하고 결과물 삭제·이용 중단을 할 수 있다(제7조 ⑬) ([Maps 약관 PDF](https://xv-ncloud.pstatic.net/images/provision/%5B%EB%AF%BC%EA%B0%84%5DMaps%EC%84%9C%EB%B9%84%EC%8A%A4%EC%9D%B4%EC%9A%A9%EC%95%BD%EA%B4%80_v0.4_(CLEAN)_1742433558704.pdf)). 맵샷의 목적이 사용자가 이미지를 저장해 쓰게 하는 것이므로, 화면 표시 자체는 정상 사용이어도 캡처 안내는 제7조 ⑨의 "복제·저장"을 유도한다고 볼 여지가 있다. 반면 제7조 ⑨가 "회사의 사전 동의 없이"라고 쓰여 있어 **1:1 문의로 동의나 해석을 받는 길은 문언상 열려 있다.** NCP의 공식 FAQ·포럼에서 이미지 저장·인쇄 답변은 찾지 못했다(확인 필요). 무료 이용량은 Maps API를 처음 쓴 '대표 계정'에만 준다 ([Maps 개요](https://guide.ncloud-docs.com/docs/application-maps-overview)). 구 AI NAVER API 상품은 2025-07-01부터 무료량이 끝났으므로 ([NCP 공지 528](https://www.gov-ncloud.com/support/notice/all/528)) 현재 키가 신규 Maps 상품의 Application인지 콘솔에서 확인해야 한다.

### 구글: 위성을 도면 배경으로 쓰는 용도와 가장 강하게 부딪힌다

현행 GMP ToS(2026-08-26 수정)는 서비스 밖 사용을 위한 export·store·rehost와 타일 대량 다운로드를 금지하고(§3.2.3(a)), SST가 허용하지 않는 캐싱을 금지하며(§3.2.3(b)), SST가 캐싱을 허용하는 것은 place_id 같은 ID 값뿐이다 ([GMP ToS](https://cloud.google.com/maps-platform/terms), [GMP SST](https://cloud.google.com/maps-platform/terms/maps-service-terms)). 더 큰 문제는 §3.2.3(c)다. **"trace or digitize roadways, building outlines… from the Maps JavaScript API Satellite base map type"**를 금지 예시로 들어, 계획도면 배경에서 도로·건물을 따라 그리는 실무 사용과 사실상 겹친다. §3.2.3(e)는 Google 지도를 non-Google 지도와 함께 쓰는 것도 금지해, 같은 화면에 브이월드 레이어를 겹치는 기능과 충돌한다. 예외는 비약관 문서인 지오 가이드라인이 "Business documents such as company reports, proposals, presentations"의 인쇄를 허용한 것인데, 같은 문서가 "Satellite View imagery falls under the same commercial restrictions as Google Earth"라고 하고 Earth의 금지 예시에 "Construction site locations"가 있다 ([지오 가이드라인](https://about.google/brand-resource-center/products-and-services/geo-guidelines/)). 공식 제품 중 Static API는 640×640(scale 2에서 1280px)이 한계이고 ([Maps Static API](https://developers.google.com/maps/documentation/maps-static/start)), 2018년 구판 ToS는 문서상 크기보다 큰 지도를 만들려고 정적 이미지를 이어 붙이는 것을 명시적으로 금지했다 ([구판 ToS 2018-02](https://developers.google.com/maps/terms-20180207)). Map Tiles API는 "Offline uses"를 금지 용도로 명시했다 ([Map Tiles Policies](https://developers.google.com/maps/documentation/tile/policies)). Google Earth 디자인의 PNG 다운로드 허용(SST §8.3.1)은 Google 콘텐츠가 식별되지 않을 만큼 변형된 사용자 데이터에만 적용되고, §8.3.2는 건설·구조설계 용도를 배제한다 ([GMP SST](https://cloud.google.com/maps-platform/terms/maps-service-terms)). 결론적으로 **구글은 현행 '사용자 캡처' 방식에서도 회색지대이고, 어떤 형태의 내보내기 기능도 붙이면 안 되는 사업자**다.

### 브이월드: 영리 허용, 캡처 전제, 저장만 승낙 대상

브이월드 오픈API 이용약관(2026-10-30 시행)은 다른 사업자와 방향이 다르다. 회원은 "운영기관의 사전 승낙 없이 서비스를 이용하여 영리 행위를 할 수 있"고(제20조 ③), 결과물과 **"오픈플랫폼 지도서비스 등 캡처화면"에 출처를 표기**해야 한다(제13조 ⑨). 즉 캡처는 약관이 예정한 사용이다. 다만 "데이터는 무단으로 저장하지 못합니다"(제19조 ⑥)와 "사전 승낙 없이 복사, 복제, 변경 … 타인에게 제공할 수 없습니다"(제19조 ④)가 있어, **타일을 합성해 파일로 넘기면 승낙이 필요하다**고 보는 것이 안전하다 ([브이월드 이용약관](https://www.vworld.kr/v4po_prcint_a001.do)). 운영기관이 과거 3D 데이터 저장 기능을 가진 프로그램에 기능 삭제를 요청한 2차 보도가 있어 이 조항은 실제로 집행된다 ([VW LAB](https://www.vw-lab.com/53)). 기술 조건은 가장 좋다. 위성(Satellite)·하이브리드 타일은 줌 19까지 나오고 ([WMTS 가이드](https://www.vworld.kr/dev/v4dv_wmtsguide_s001.do)), 이번 실측(2026-11-25, curl)에서 `api.vworld.kr`·`xdworld.vworld.kr` 타일은 `Access-Control-Allow-Origin: *`를 돌려줬다. 반면 카카오 타일은 이 헤더가 없어 canvas 내보내기가 원천적으로 막힌다 ([MDN: CORS 이미지와 canvas](https://developer.mozilla.org/en-US/docs/CORS_Enabled_Image)). 키당 호출 한도 수치는 약관이 "별도로 공지"라고만 해 확인 필요다.

국토지리정보원 정사영상을 직접 받아 서빙하는 길은 막혀 있다. 같은 기관 자료인데 정사영상은 "제한 없음" ([data.go.kr 15059919](https://www.data.go.kr/data/15059919/fileData.do)), 국토영상정보(항공사진)는 공공누리 **제3유형 출처표시·변경금지**로 표시가 엇갈리고 ([data.go.kr 15015483](https://www.data.go.kr/data/15015483/fileData.do)), 전국 TIFF를 타일 서버로 돌리면 저장·전송 비용이 생겨 무료 한도 원칙과 맞지 않는다.

## 경계선은 '누가 픽셀을 만들어 내보내나'에 있다

다섯 사업자의 답을 하나로 묶으면 판단 기준은 처리 위치(서버냐 브라우저냐)가 아니라 **지도 픽셀을 파일로 만드는 주체가 맵샷 코드냐, 사용자의 브라우저 기본 기능이냐**다. 구글 노트가 지적하듯 브라우저 canvas 합성도 "Customer가 export를 가능하게 만드는 구조"이면 §3.2.3(a)와 그 서문의 "will not permit a third party to"에 걸린다 ([GMP ToS](https://cloud.google.com/maps-platform/terms)). 카카오도 같은 결이다. 사용자의 스크린샷·브라우저 PDF 출력은 허용하고, 자동 대량 캡처나 문서 생성 배포는 범위 밖으로 둔다. 지금의 '5000px SDK 지도 + 확장/DevTools 캡처'가 부자연스러운 이유는 바로 이 경계선 위에 서기 위해서다. 맵샷 코드는 지도를 한 번 띄울 뿐이고, 픽셀을 떠서 파일로 만드는 일은 사용자의 도구가 한다.

이 기준으로 보면 후보는 세 부류로 나뉜다. **경계 안쪽**(사용자의 브라우저 기본 기능이 파일을 만든다)에는 현행 캡처, 브라우저 인쇄(PDF 저장), 자체 확장이 있다. 자체 확장은 UX만 바꾸고 약관상 위치는 현행과 같다. **경계 바깥이지만 승낙으로 넘을 수 있는 것**에는 브이월드 타일 브라우저 합성과, 카카오·네이버에서 getDisplayMedia로 탭 화면을 패닝하며 이어 붙이는 방식이 있다. 후자는 서버가 타일을 저장하지 않고 화면에 보인 픽셀만 쓰지만, 이어 붙여 PNG로 인코딩하는 것은 맵샷 코드다. **경계 바깥이고 승낙 가능성도 낮은 것**에는 정적 지도 이어 붙이기, 구글 Map Tiles 합성, 서버 헤드리스 렌더링, 타일 프록시가 있다. 프록시로 CORS를 우회하는 것은 카카오가 차단 대상으로 든 "안내된 방법과 다르게 직접 접근"에 그대로 해당한다 ([DevTalk 146390](https://devtalk.kakao.com/t/api/146390)).

## 후보 10개를 다섯 기준으로 비교하면 둘만 남는다

화질은 5000×5000 기준, 비용은 무료 한도 안에서 건당 소비량으로 평가했다. 반경 10km를 5000px에 담으면 약 4m/px, 반경 1km는 약 0.4m/px라는 계산은 추정이다.

| 후보 | 약관 적합성 | 화질 | 구현 난이도 | 비용(무료 한도) | 사용자 경험 |
|---|---|---|---|---|---|
| A. 현행: SDK 큰 지도 + 사용자 확장/DevTools 캡처 | 카카오 양호(로고 유지 조건), 네이버·구글 회색 | 높음, 이음매 없음 | 이미 구현 | 카카오 SDK 로드 1회=1건, 무료 일 300,000건 ([쿼터](https://developers.kakao.com/docs/ko/getting-started/quota)) | 나쁨: 확장 설치·DevTools 조작 |
| B. 브라우저 인쇄 버튼(`window.print()` + 지도 크기 `@page`) | 카카오는 개인 목적 PDF 출력 허용 답변 있음. 네이버·구글은 A와 같음 | 큰 페이지 인쇄 시 품질·분할은 확인 필요 | 낮음 | A와 같음 | 보통: 버튼 → 인쇄창에서 'PDF로 저장' |
| C. 브이월드 WMTS 브라우저 canvas 합성 → PNG 다운로드 | 영리 허용·캡처 전제. 파일 제공은 **승낙 필요** | 높음(위성 줌 19, 이음매 없음) | 낮음(CORS 열림, 서버 불필요) | 서버 비용 0. 키 호출 한도 확인 필요, 건당 약 400타일(추정) | **최상: 버튼 한 번** |
| D. getDisplayMedia 탭 캡처 + 자동 패닝 + 합성 | 카카오 회색(자동 캡처, 합성), 네이버 회색, 구글 위반 소지 | 중상: 라벨 경계 중복·잘림 처리 필요 | 중상 | A와 같음 | 중: 매번 공유 허락 창, 데스크톱 크롬 위주 |
| E. 맵샷 전용 크롬 확장 | A와 같은 위치(사용자 브라우저가 캡처) | 높음(전체 캡처) | 중: 웹스토어 심사·단일 목적 정책 ([CWS 정책](https://developer.chrome.com/docs/webstore/program-policies/policies)) | 0 | 중: 설치 장벽은 그대로 |
| F. 정적 지도 여러 장 이어 붙이기 | 세 사업자 모두 위반 소지(가공·저장, 구판 구글 명시 금지) | 이음매·라벨 중복 | 중 | 카카오 1장 최대 4096×2048, 무료 일 1,000건 ([REST 문서](https://developers.kakao.com/docs/ko/kakaomap/rest-api)), 네이버 1,024px ([Static Map](https://api.ncloud-docs.com/docs/ai-naver-mapsstaticmap-raster)), 구글 1280px·월 10,000건 ([가격](https://developers.google.com/maps/billing-and-pricing/pricing)) | 좋음 |
| G. Google Map Tiles API 합성 | "Offline uses" 금지 | 높음 | 중 | 건당 약 400타일, 월 무료 100,000타일로 약 250건, 일 기본 쿼터 15,000타일 ([Usage and Billing](https://developers.google.com/maps/documentation/tile/usage-and-billing)) | 좋음 |
| H. 서버 헤드리스 렌더링 | 자동화 접근·서버 생성·배포로 세 사업자 모두 위험. 카카오 Selenium 불허 답변 | 높음 | 중상 | Chromium에 1~2GiB 메모리가 필요해 기존 소형 서버에는 부적합 ([OneUptime](https://oneuptime.com/blog/post/2026-09-13-puppeteer-browser-lifecycle-cloud-run/view)) | 좋음 |
| I. 해외 상용 위성 API(Stadia·Mapbox·MapTiler·Esri·Azure) | Stadia cacheable static만 인쇄 명시 허용, Esri는 대량 수확 금지 | 국내 화질·최신성 비교 자료 없음(확인 필요) | 중 | Stadia 위성은 Standard $80/월부터, MapTiler 정적 지도는 무료 플랜 불가 ([Stadia](https://stadiamaps.com/pricing/), [MapTiler](https://docs.maptiler.com/cloud/api/static-maps/)) | 좋음 |
| J. 국토지리정보원 정사영상 자체 서빙 | 라이선스 표시 충돌(제한 없음 vs 3유형 변경금지), 보안 규정 | 높음(12/25cm 원본) | 상 | 스토리지·전송 비용 발생 | 좋음 |

**C가 유일하게 다섯 기준 모두에서 높은 점수를 받고**, 약한 고리는 약관 적합성 하나인데 그것은 무료 서면 문의로 해소할 수 있는 종류다. 화질 면에서도 브이월드 위성은 국토지리정보원 항공사진 계열로 보이며(원천·촬영연도는 확인 필요), QGIS 사용자들이 이미 공식 플러그인으로 배경지도로 쓰고 있어 ([V_QGIS](https://plugins.qgis.org/plugins/V_QGIS/latest/)) 도시계획 실무자에게 익숙한 영상이다. 카카오·네이버 스카이뷰와의 화질 비교 자료는 없으므로 같은 좌표로 직접 비교해야 한다(확인 필요).

**B는 카카오·네이버 지도에 남는 가장 자연스러운 개선**이다. 카카오가 허용한 것은 "브라우저 기본 기능을 통한 개인 목적 PDF 출력"이고, 버튼은 그 기본 기능을 여는 단축키 역할만 한다. 다만 출력물을 도면·보고서로 배포하는 경우는 같은 답변이 제외한 "문서를 생성하여 배포"와 겹치므로 문의 대상에 넣는다. 5000px 지도를 한 페이지 PDF로 뽑을 때의 해상도·분할 동작은 실측하지 않았다(확인 필요).

D는 확장 없이 픽셀을 뜰 수 있는 유일한 웹 표준 경로다. `getDisplayMedia`는 매번 사용자 허락이 필요하고 ([MDN getDisplayMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia)), Element Capture는 크롬 132 이상 데스크톱에서만 된다 ([Chrome Element Capture](https://developer.chrome.com/docs/web-platform/element-capture)). 화면에 보이는 영역만 잡히므로 5000px를 만들려면 지도를 격자로 옮기며 여러 프레임을 이어 붙여야 한다. 이 '자동 캡처 + 합성'은 카카오가 단일 화면 자동 캡처는 허용했지만 여러 화면 합성에는 답하지 않았고, Selenium 대량 캡처는 불허했다는 점에서 **답변을 받기 전에는 출시하지 않는다.** 구글 지도에는 적용하지 않는다.

## 어느 경로든 지켜야 할 네 가지 선

첫째, **출처·로고는 산출물 안에 남긴다.** 카카오는 저장 이미지에도 로고와 저작권 표시를 유지하라고 했고 ([DevTalk 152313](https://devtalk.kakao.com/t/topic/152313)), 구글은 표기를 가리거나 지우지 못하게 하며 ([GMP ToS](https://cloud.google.com/maps-platform/terms)), 브이월드는 캡처화면에 운영기관이 정한 방식으로 표기하라고 한다. 5000px 페이지에서 SDK 로고가 캡처 범위 안에 들어가는지, 브이월드 합성 이미지에 출처 문구를 그려 넣는지를 기본값으로 점검한다.

둘째, **산출물에 좌표를 넣지 않는다.** 국가공간정보 세부 분류기준은 공개 항공사진도 "인터넷, 네비게이션, 휴대폰에는 좌표 표시 불가"로 두고, 2차원 좌표가 포함된 30m보다 정밀한 자료를 '공개제한'으로 분류한다 ([국가공간정보 세부 분류기준](https://www.law.go.kr/LSW/flDownload.do?flSeq=160677163)). 도시계획 실무자는 CAD 정합용 GeoTIFF나 월드파일을 원하겠지만, 이 기능은 별도 확인 전까지 만들지 않는다. 이 별지가 속한 규정의 정확한 명칭·시행일은 확인 필요다. 25cm보다 정밀한 항공사진 제한은 반경 1km(약 0.4m/px, 추정)에서도 걸리지 않는다.

셋째, **'트레이싱'·'디지타이징'을 홍보 문구에 쓰지 않는다.** 구글 §3.2.3(c)(i)이 위성 베이스맵의 도로·건물 윤곽 트레이싱을 금지 예시로 든다 ([GMP ToS](https://cloud.google.com/maps-platform/terms)). "도면 배경" 정도로 표현한다.

넷째, **지도 이미지 생성 기능에는 과금하지 않는다.** 카카오 FAQ는 상업 서비스 사용은 제한하지 않지만 API 활용 기능에 별도 과금은 허용하지 않는다 ([DevTalk FAQ](https://devtalk.kakao.com/t/faq-api/125610)). 광고 수익 모델은 문제없지만 유료 다운로드나 화질별 요금제는 이 조항에 걸린다.

## 추천 순위와 단계별 실행안

추천 순위는 **① 사전 승낙·서면 해석 요청 → ② C 브이월드 원클릭 다운로드 → ③ B 인쇄 버튼 → ④ A 현행 방식 유지(안내 개선) → ⑤ D getDisplayMedia(카카오 긍정 답변 시에만) → ⑥ E 자체 확장(보류)**이다. F~J는 배제한다. ①은 비용이 0이고 되돌릴 필요가 없으며, 나머지 모든 단계의 리스크를 낮춘다. ②는 승낙 문서가 오기 전에도 개발과 로컬 검증까지는 진행하고, 공개만 승낙 뒤로 미룬다.

| 단계 | 할 일 | 끝난 기준 | 비용 |
|---|---|---|---|
| 1. 문의 발송(이번 주) | 브이월드 운영기관(공간정보산업진흥원)에 "WMTS 위성/배경 타일을 사용자 브라우저에서 합성해 출처를 넣은 단일 이미지(최대 5000px, 좌표 미포함)를 무료·광고 수익 서비스에서 내려받게 하는 것"의 승낙과 키 호출 한도, 출처 표기 문구를 묻는다. 도시계획 레이어를 서버로 중계·캐시하는 부분도 같은 문의에 넣는다. 카카오 DevTalk에 맵샷 구조(단일 SDK 지도, 사용자 수동 캡처·브라우저 PDF, 로고 유지, 도면 배경 사용, 탭 캡처 합성 계획)를 공개 질문으로 올린다. ## Conclusion

이번 조사로 바뀐 판단은 "약관 때문에 원클릭이 불가능하다"가 아니라 **"원클릭은 승낙의 문제이고, 승낙을 받을 수 있는 곳은 공공 쪽이다"**라는 것이다. 민간 지도사 약관은 저장을 원칙적으로 막고 예외를 개인 캡처에만 열어 두었지만, 브이월드는 영리 이용과 캡처를 약관에서 먼저 인정했고 기술적으로도 서버 없이 브라우저만으로 합성할 수 있다. 그러니 맵샷이 원클릭 대형 위성 이미지를 얻으려면 기술 우회가 아니라 운영기관 문의를 먼저 해야 한다. 승낙을 받으면 위성 배경의 기본 소스를 카카오 스카이뷰에서 브이월드로 옮길 근거가 생기고, 촬영 시점을 알 수 없는 카카오 영상의 약점([DevTalk 151446](https://devtalk.kakao.com/t/skyview/151446))도 함께 해소할 여지가 있다.

남는 위험은 캡처 방식 자체보다 사용자가 결과물을 쓰는 방식에 있다. 발주처 제출 도면에 넣는 행위, 위성 위 트레이싱, 좌표 정합 요구는 어느 사업자의 허용 문구에도 명확히 들어 있지 않다. 따라서 맵샷이 결과물의 용도를 보증하는 문구("납품물에 써도 됩니다")를 쓰지 않고 출처·로고·좌표 원칙을 코드 기본값으로 굳히는 것이 승낙 여부와 관계없이 지켜야 할 선이다.
