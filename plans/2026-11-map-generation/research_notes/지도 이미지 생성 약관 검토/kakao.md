## 2. 캡처·인쇄·PDF·보고서/도면 사용에 대한 카카오 측 답변

### Takeaway
DevTalk 답변 패턴: **사용자 개인의 화면 캡처·브라우저 인쇄는 허용(로고·저작권 표시 유지)**, **자동 캡처·대량 수집·타일 병합·오프라인 제공·캡처 이미지를 문서로 만들어 배포하는 것은 불허/범위 밖**. 캡처 이미지를 영상 등 2차 결과물에 쓸 때는 카카오 로고가 포함된 상태로 써야 한다.

### Cited Findings
- 단일 지도 화면 자동 캡처 → 사용자 기기 보관: "개인 사용자의 화면 캡처와 같은 범위로 보아 사용하셔도 됩니다." / "저장된 이미지에서도 카카오 로고와 저작권 표시는 유지해주세요." / "오프라인 지도 탐색 기능으로 제공하는 형태는 해당 범위에 포함되지 않습니다." (C.L, 2026-10-23) — [DevTalk 152313](https://devtalk.kakao.com/t/topic/152313)
- 로드뷰 임베드 페이지의 PDF 인쇄: "로드뷰 이미지를 직접 캡쳐, 저장, 가공 등 문서를 생성하여 배포하는 케이스가 아니라면," "사용자 브라우저의 기본 기능을 통한 개인 목적의 PDF 출력은 데이터 별도 저장 에 해당하지 않아 사용 가능합니다." (Map, 2026-08-12) — [DevTalk 151107](https://devtalk.kakao.com/t/pdf/151107)
- 로드뷰 Selenium 자동 캡처 500~1000장 + AI 학습: "로드뷰 화면의 캡쳐 및 AI 활용은 정책 상 허용하지 않으며," "실시간 API 호출로만 이용 부탁드립니다." (Map, 2026-10-06) — [DevTalk 151931](https://devtalk.kakao.com/t/ai/151931)
- 지도 포함 컴포넌트 PDF 추출(html2canvas): "오프라인 사용 가이드에 맞춰 라이브러리를 사용하지 않고 이미지를 컨버스로 옮기는 로직을 직접 구현하거나" "스크린샷으로 지도를 캡처해주세요." (lea.ju, 2023-02-02) — [DevTalk 127514](https://devtalk.kakao.com/t/pdf-html2canvas/127514)
- 공공기관 홍보영상에 일반지도·스카이뷰 캡처 사용: 출처 표기만으로 되느냐는 질문에 "영상물 내 보여지는 지도 이미지에도 kakao 로고가 삽입된 화면을 캡쳐하여 사용해주세요." (KakaoMap, 2024-05-06) — 즉 캡처 이미지를 2차 결과물(영상)에 쓰는 것 자체는 로고 포함 조건으로 용인 — [DevTalk 136914](https://devtalk.kakao.com/t/topic/136914)
- 같은 글에서 질문자가 "카카오 맵 영상물 활용 오프라인 가이드"의 존재를 언급 — [DevTalk 136914](https://devtalk.kakao.com/t/topic/136914)

### Inferences
- 맵샷 현행 구조(사용자가 자기 브라우저에서 공식 SDK 지도를 보고 GoFullPage/DevTools 로 직접 캡처)는 "개인 사용자의 화면 캡처" 범주에 가장 가깝다. 이 경우 **캡처본에 카카오 로고·저작권 표시가 남아 있어야** 한다(지도 우하단/좌하단 로고를 CSS 로 가리면 안 됨, 5000px 페이지에서 로고가 캡처 범위 안에 들어가는지 확인 필요).

- "5000×5000 단일 SDK 지도"는 여러 화면을 병합하지 않는 단일 화면이라는 점에서 타일 병합보다 유리하지만, 카카오가 "개인 사용자 화면 캡처 범위"로 볼지는 크기에 관한 답변이 없어 미확정.

## 3. 정적 지도(Static Map) — 크기·약관·병합

### Takeaway
두 종류가 있다. (a) JS SDK `kakao.maps.StaticMap`(이미지 1장으로 지도 표시), (b) 2026-07-21 신설된 **정적 지도 조회 REST API** `GET https://dapi.kakao.com/v2/maps/staticmap` — 최대 `2048x1024`(scale=2 시 응답 4096×2048), 로고 제거 불가, 무료 일 1,000건 후 건당 2원. 지도 타입(스카이뷰/하이브리드) 지원 여부는 문서에서 확인 못함. 여러 장 병합을 허용한다는 문구는 없고, "한번 생성된 URL 재사용 제한"·"저장 사용 금지" 원칙상 병합·보관은 위험.

### Cited Findings
- REST 정적 지도: `size` 필수, "최대 `2048x1024`", `lv` 1~15, `format` png/jpg, `scale` 1 또는 2(기본 2, 2이면 응답이 size 의 2배), `logo_pos` 4방향, `coord` WGS84/WCONGNAMUL/WTM/TM, 마커 최대 5개 — [카카오맵 REST API 문서](https://developers.kakao.com/docs/ko/kakaomap/rest-api)
- 응답 이미지에 카카오 CI 로고 포함, `logo_pos` 로 위치만 조정·제거 불가 — [카카오맵 REST API 문서](https://developers.kakao.com/docs/ko/kakaomap/rest-api)
- 신설 공지(게시 2026-06-16, 적용 2026-07-21): 신규 4종 중 "정적 지도 조회", 첫 번째 활성화 앱 무료 일 1,000건, 유료 건당 2원; 두 번째 앱부터/초과 시 비즈월렛 연결 필요 — [DevTalk 공지 150222](https://devtalk.kakao.com/t/api-notice-on-new-kakao-map-api-features-and-free-quota-policy/150222)
- JS SDK 레퍼런스 색인에 `StaticMap` 클래스(setCenter/getCenter/setLevel/getLevel/setMapTypeId/getMapTypeId) 존재. `setMapTypeId` 가 있어 지도 타입 지정은 가능해 보이나 크기 제한·약관 설명은 문서 본문(JS 렌더)을 읽지 못함 — [Kakao Maps API 문서](https://apis.map.kakao.com/web/documentation/)
- 정적지도 imageservice 에 대해 "한번 생성된 URL 로 계속 사용하시는 것은 제한됩니다." — [DevTalk 146390](https://devtalk.kakao.com/t/api/146390)
- StaticMap 이미지 호스트가 spi.maps.daum.net → spi.map.kakao.com 로 바뀐 사례 문의, 내부 리소스 경로는 예고 없이 변경 가능 — [DevTalk 149898](https://devtalk.kakao.com/t/staticmap-spi-maps-daum-net-spi-map-kakao-com/149898)

### Inferences
- REST 정적 지도는 "서버가 이미지를 받아 사용자에게 주는" 공식 경로라는 점에서 현재 구조보다 자연스럽지만, 한 장 최대 4096×2048(scale 2)이라 5000×5000 을 만들려면 여러 장 병합이 필요 → 병합·가공은 명시적 허용이 없고 "타일 병합"과 같은 우려를 다시 낳음.
- 무료 1,000건/일 × 병합 수(예: 3~6장/요청)면 하루 150~300건 생성으로 상한. 초과분 유료(2원/건)는 사전 승인 없이 쓸 수 없는 비용.
- 스카이뷰 지원 여부가 불명확하면 맵샷 핵심 수요(위성 배경)에 못 쓸 수 있음.

### Gaps
- REST 정적 지도의 maptype(스카이뷰/하이브리드) 파라미터 존재 여부 — 문서 요약에 없음, '확인 필요'.
- REST 정적 지도 응답 이미지의 저장·재배포·병합 허용 여부 — 문서에 명시 없음, '확인 필요'.
- JS `kakao.maps.StaticMap` 의 최대 크기 — 미확인.

## 4. 쿼터(일일 제공량)

### Takeaway

## 5. 스카이뷰(위성/항공) 영상의 별도 저작권 조건

### Takeaway
카카오 측 답변상 스카이뷰의 별도 제공자 조건이나 출처 표기 의무는 제시되지 않았다("출처 표기 의무는 없습니다"). 다만 촬영 시점 정보는 API 로 제공하지 않는다. 제3 제공자(항공사진 원저작자) 조건을 명시한 약관 문구는 찾지 못함.

### Cited Findings
- 영리 부동산 서비스 SKYVIEW/HYBRID: "활용 가능합니다." / "또한 출처 표기 의무는 없습니다." / "API 내 촬영 시점 관련 정보는 제공하지 않습니다." (Map, 2026-09-02) — [DevTalk 151446](https://devtalk.kakao.com/t/skyview/151446)
- API 스카이뷰·하이브리드·로드뷰 촬영 연월 정보 미공유 — [DevTalk 122754](https://devtalk.kakao.com/t/map-static-image/122754)
- 스카이뷰는 50cm급 항공사진 서비스로 소개(2009년 다음 시절 보도자료, 현재 출처와 다를 수 있음) — [카카오 보도자료 6256](https://www.kakaocorp.com/page/detail/6256?lang=ENG)

### Inferences
- "출처 표기 의무 없음"은 SDK 실시간 렌더링 맥락의 답변이다. 캡처 결과물에는 152313·136914 답변대로 로고·저작권 표시 유지가 요구되므로 둘을 혼동하지 말 것.
- 도면에 쓰는 사용자 입장에서 촬영 시점을 알 수 없다는 점은 기획 품질 이슈(국토지리정보원 정사영상 등 대안 검토 근거).

### Gaps
- 지도 화면 하단 저작권 표기 문구(예: 항공사진 제공처 표기)의 현재 실제 내용 미확인 — SDK 렌더 화면에서 직접 확인 필요.

## 6. SDK 렌더 결과를 canvas/이미지로 내보내기(CORS)

### Takeaway
카카오가 타일 CORS 를 허용한다는 공식 문서는 없다. 커뮤니티 보고상 `toDataURL` 시 tainted canvas 오류가 나며, 카카오 답변은 "라이브러리 없이 이미지를 canvas로 옮기는 로직을 직접 구현"하거나 "스크린샷" 을 권했다(2023). 공식 export API 는 없음.

### Cited Findings
- 지도 캡처 `toDataURL` 시 tainted canvas 오류, CORS 이슈로 프록시를 통해 타일을 받으라는 커뮤니티 의견 — [DevTalk 137347](https://devtalk.kakao.com/t/api/137347)
- 카카오 답변: "오프라인 사용 가이드에 맞춰 라이브러리를 사용하지 않고 이미지를 컨버스로 옮기는 로직을 직접 구현하거나" "스크린샷으로 지도를 캡처해주세요." — [DevTalk 127514](https://devtalk.kakao.com/t/pdf-html2canvas/127514)
- 리소스 도메인이 daumcdn.net 외에 kakaocdn.net 으로도 제공될 수 있다는 CSP 공지 — [DevTalk 150541](https://devtalk.kakao.com/t/csp/150541)
- 일반론: CORS 헤더 없는 교차 출처 이미지를 그린 canvas 는 export 불가 — [MDN](https://developer.mozilla.org/en-US/docs/CORS_Enabled_Image)

### Inferences
- 프록시로 타일을 받는 우회는 "가이드 외 직접 접근"(146390)에 해당 → 채택 불가.
- 따라서 "브라우저 캡처(사용자 조작)"가 카카오 측이 직접 권한 경로이기도 하다(127514). 현행 방식이 카카오 답변과 가장 정렬된 형태.

### Gaps
- 현재(2026) 타일 응답의 `Access-Control-Allow-Origin` 헤더 실측 안 함 — 로컬에서 네트워크 탭으로 확인 필요. 허용돼 있더라도 정책상 canvas export 허용과는 별개.
- 127514 답변이 언급한 "오프라인 사용 가이드"의 원문 미확인.

## 종합 판단(조사자 의견)
- 현행 방식(공식 SDK 단일 지도 + 사용자 수동 캡처)이 카카오 답변들과 가장 잘 맞는다. 유지 조건: ① 로고·저작권 표시를 가리지 않고 캡처 범위에 포함, ② 서버·헤드리스 자동 캡처나 이미지 파일 배포로 바꾸지 않음, ③ 타일 URL 직접 호출·프록시·캐시 금지.
- 정적 지도 REST API 는 공식이지만 2048×1024(×2) 상한·일 1,000건·스카이뷰 미확인·병합 허용 불명 때문에 5000px 위성 배경 용도에는 부적합 가능성이 높다.
- 가장 큰 미확정 리스크: "캡처본을 도면/보고서에 넣어 제3자에게 제출"이 "개인 캡처"인지 "문서 생성 배포"인지. DevTalk 에 맵샷 구조(단일 SDK 지도 최대 5000px, 사용자 수동 캡처, 로고 유지, 도면 배경 사용)를 설명해 서면 답변을 받아 두는 것을 권장.
