# 2단계: 보도자료 풀이 글 (도시뉴스 두 갈래)

> 상태: 구현 중 · 시작: 2026-11-25 · 관련 레포: API, Front
> 브랜치: 1단계와 같은 `feat/city-news-map` 에 이어서 작업
> 1단계(지도 레이어)는 [README.md](README.md), 수집·지역 추출은 [flow.md](flow.md)

## 왜 하나

- 지도 소식을 누르면 국토부 원문(문서뷰어·PDF)으로 바로 나간다. PDF 를 끝까지 읽을 사람은 거의 없고, 나가는 순간 체류가 끝난다.
- 지역이 없는 소식(제도·통계·전국 정책)을 지도 패널 아래 '전국 단위 소식'으로 묶어 보여주는 건 지도와 상관없는 정보라 화면만 복잡하게 만든다.
- 보도자료마다 우리 글이 있으면 검색 유입 통로가 생긴다("○○시 도심융합특구" 같은 검색).

## 무엇을 만드나

도시뉴스를 두 갈래로 운영한다.

| 갈래 | 단위 | 원천 | 지금 |
|---|---|---|---|
| 브리핑 | 하루 1편 | 네이버 뉴스 검색 → LLM 묶음 요약 | 운영 중(`plans/2026-06-news-ai-digest/`) |
| 보도자료 풀이 | 보도자료 1건 = 글 1편 | 국토부 보도자료 본문(PDF) → LLM 정리 | **이번에 추가** |

- 보도자료를 수집하면 풀이 글을 만들어 도시뉴스에 올린다. 지역이 있든 없든 모두.
- 지도 소식 항목의 주 버튼은 '도시뉴스에서 읽기'(새 탭). 원문 링크는 보조로 남긴다.
- 지도 패널의 '전국 단위 소식' 묶음은 뺀다. 지역이 없는 소식은 도시뉴스에서만 보인다.
- 풀이 글 화면: 한 줄 요약 → 핵심 → 대상 지역·일정 → 실무자에게 의미 → 출처와 원문 링크.
  대상 지역이 있으면 '맵샷 지도에서 이 지역 보기' 버튼으로 지도(도시소식 켠 상태)로 돌아간다.

## 범위

이번에 하는 것

- API: 풀이 글 생성(수집 회차마다), 저장, 목록·상세 조회, 지도 응답에 글 번호 포함
- Front: 도시뉴스 탭 두 갈래(브리핑 / 보도자료 풀이), 풀이 글 화면, 지도 항목 → 우리 글 연결, 전국 묶음 제거, 지도로 돌아오는 링크
- 관리 화면: 풀이 글 보기(기존 게시글 관리 재사용), 수동 수집 버튼

이번에 안 하는 것

- 다른 부처·지자체 보도자료: 1단계 남은 일과 같다.
- 브리핑과 풀이의 합치기(예: 브리핑에 그날 풀이 글 링크): 두 갈래가 자리 잡은 뒤 본다.

## 결정

- **트랙은 게시글 작성자로 나눈다.** 브리핑은 기존 `도시뉴스`, 풀이는 `도시소식`. 게시글 테이블에 갈래 컬럼을 새로 두지 않아도 되고, 기존 브리핑 조회(`writer = 도시뉴스`)가 그대로 동작한다.
  - 버린 것: `post_type` 컬럼 추가 → 기존 글 백필과 조회 조건 변경이 따라와서 이득이 없다.
- **풀이 데이터는 게시글의 별도 JSON 컬럼(`explainer_json`)에 둔다.** 브리핑 JSON(`digest_json`)과 모양이 달라 같은 컬럼을 쓰면 파서가 갈래를 알아야 한다. `content` 에는 같은 내용을 HTML 로도 넣어 목록 미리보기·폴백에 쓴다.
- **보도자료 ↔ 글 연결은 `press_release.post_id`.** 한 보도자료에 글 하나. 글이 있으면 다시 만들지 않는다.
- **LLM 은 본문에 있는 것만 쓴다.**
  - 입력: 제목, 부제(국토부 공식 요약), 본문(PDF 추출, 앞부분 최대 15,000자), 담당부서.
  - 출력(JSON): 한 줄 요약, 핵심 3~5개, 대상 지역(텍스트), 일정(날짜와 내용), 실무자에게 의미.
  - 숫자·날짜·사업명은 본문 표현 그대로. 본문에 근거가 없는 항목은 빈 값. 추측·전망·평가 금지.
  - 지역 좌표·코드는 LLM 이 아니라 1단계 행정구역 사전 결과를 쓴다(공통 규칙 5).
  - 한 번에 최대 5건씩 묶어서 부른다(무료 티어 레이트리밋, 공통 규칙 5). 하루 보도자료 5~10건이라 1~2회.
    → 번복(2026-11-25): 운영 첫 수집에서 5건 묶음 응답이 토큰 한도에 잘려 7건 모두 부제 폴백이 됐다. 유료 할당을 붙이기로 해서 한 건씩, 본문 최대 1만 5천 자로 부른다(실패 시 1회 재시도). 부제 폴백 글은 다음 회차에 다시 써서 갱신한다. Mapshot-API PR #141
- **LLM 이 실패해도 글은 만든다.** 국토부 부제를 핵심으로 쓴 글로 대신하고, 다음 회차에 다시 만들지 않는다. 지도 항목이 글로 연결돼야 해서 '글 없음' 상태를 오래 두지 않는다.
- **'AI 가 찍어낸 글'로 보이지 않게 한다.**
  - 글 머리에 "국토교통부 보도자료를 정리한 글" 과 출처·원문 링크를 항상 둔다(공공누리 제1유형, 출처 표시).
  - 형식을 고정하고(무엇·어디·언제·의미), 지도로 이어지는 버튼을 붙여 원문을 다시 쓴 것 이상의 쓸모를 준다.
  - 검색 노출은 처음엔 막는다(`noindex`). 풀이 글 품질을 한두 주 보고 운영자가 연다(빌드 환경변수 `VUE_APP_PRESS_INDEXABLE=true`).
    배경: 자동 생성 페이지를 대량으로 만들면 검색엔진 스팸 정책(scaled content abuse)과 애드센스 저품질 판정 위험이 있다.
- **지도에서 우리 글은 새 탭으로 연다.** 같은 탭이면 지도 위치·선택이 사라져서, 여러 소식을 차례로 보기 어렵다.
