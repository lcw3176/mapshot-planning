# 출력 범위: 세 지도 회사를 같은 땅 범위로 맞추고, 분홍 칸은 실제 출력 범위로 그린다

> 2026-11-26. 관련 PR: Mapshot-API #145, Mapshot-Front #87

## 문제
같은 중심·반경인데 카카오 출력만 네이버·구글과 경계가 달랐고, 프론트 분홍 칸도 어느 출력과도 2~10% 어긋났다.

## 원인 (로컬에서 카카오 SDK 로 실측)
1. 카카오 템플릿이 `setCenter()` → `relayout()` 순서라 출력이 마지막 크기 증가분 절반(250px)만큼 동·남으로 밀렸다. 반경 10km 에서 동·남 각 약 1km.
2. 카카오는 TM(EPSG:5181)이라 level 마다 m/px 가 고정, 네이버·구글은 웹 메르카토르라 위도가 높을수록 1px 가 덮는 땅이 cos(위도)만큼 준다. 서울에서 카카오가 약 5.5% 넓었다.
3. 카카오 TM 은 중앙경선 127°E 에서 멀수록 진북과 기운다. 부산·강릉 약 1.2°, 울릉 약 2.4°.
4. 분홍 칸은 회사와 무관한 고정 위경도 폭(mapshot.min.js Tile)이었다.

## 결정
- 기준은 네이버·구글(웹 메르카토르) 범위. 카카오 캔버스를 `1.19432 × cos(위도)` 배로 줄여 같은 땅 길이를 덮는다(1.19432 = 156543.034 / 2^17).
- 카카오는 `relayout()` 을 먼저 부른다.
- 분홍 칸은 세 회사 모두 같은 크기로, 미리보기(카카오) 화면에 반듯한 정사각형으로 그린다(`Mapshot-Front src/assets/js/captureBounds.js`). 카카오 출력과는 정확히 같고, 네이버·구글은 동쪽 지역에서 모서리가 조금 어긋난다(울릉 10km 약 560m). 칸이 기울어 보이는 게 더 어색하다고 봤다.
- 카카오의 기울기(3번)는 고치지 않았다. 지도를 CSS 로 돌리면 글자가 기울고 영상이 흐려진다. 필요하면 따로 정한다.

## 바꿀 때 주의
- 템플릿의 줌·캔버스 크기를 바꾸면 `captureBounds.js` 의 표도 같이 바꾼다.
- 템플릿 `<script>` 안에 한글 주석을 쓰면 응답에서 `?` 로 깨진다. 설명은 Thymeleaf 파서 주석 `<!--/* */-->` 에 쓴다.
