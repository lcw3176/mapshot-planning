# 지도 SDK 리소스는 공식 로더로만 부르고, 지도 이미지 저장을 서비스가 지시하지 않는다

> 날짜: 2026-11-25 · 영향 레포: Front, API

## 계기

- 카카오맵이 2026-11 공지로 SDK 내부 리소스(스크립트·지도 타일·로드뷰 등)의 직접 호출·별도 저장을 허용하지 않는다고 다시 안내했다.
  `*.daumcdn.net` 리소스 제공은 2026-11-30 에 끝나고, 도메인만 `kakaocdn.net` 으로 바꾸는 것도 올바른 조치가 아니라고 했다.
- 점검해 보니 SDK 로더(`//dapi.kakao.com/v2/maps/sdk.js`)는 공식 방식이었지만, 장소 검색 목록·마커에 카카오 공식 예제의 이미지
  (`t1.daumcdn.net/.../mapapidoc/marker_number_blue.png`, `places_jibun.png`)를 직접 주소로 쓰고 있었다.
- 사용법 페이지에 "그 화면을 캡처해서 저장하시면 돼요" 처럼 서비스가 지도 이미지 저장을 직접 지시하는 문구가 있었다.
  지도 회사 약관은 저장·복제를 막고 있고, 허용 쪽으로 해석되는 건 이용자 본인의 화면 캡처 정도다.

## 결정

- 지도 SDK 는 공식 로더 URL 로만 불러온다. SDK 가 내부적으로 쓰는 리소스나 예제 이미지 주소를 코드에 직접 쓰지 않고, 내려받아 저장하지도 않는다.
  - 장소 검색 번호 마커는 직접 그린 SVG(지도 위 핀과 목록이 같은 그림), '지번' 표시는 CSS 배지로 바꿨다(Mapshot-Front #85 외).
- 서비스 문구는 지도 이미지를 '저장하라', '캡처하라'고 지시하지 않는다. "그 화면을 활용하시면 돼요" 처럼 쓰고,
  캡처는 '브라우저 기능으로 화면을 담는 방법' 소개로만 둔다.
- 캡처 안내에는 지도 회사 로고·저작권 표시를 지우지 말라는 문구를 함께 둔다.

## 버린 선택지

- 예제 이미지 주소를 `kakaocdn.net` 으로만 바꾸기: 지금은 열리지만 같은 '리소스 직접 호출'이고, 주소가 또 바뀌면 깨진다.
- 예제 이미지를 내려받아 우리 서버에 두기: 공지가 금지하는 '별도 저장'이다.

## 이 결정을 다시 볼 조건

- 지도 회사가 정적 지도·이미지 내보내기를 공식으로 허용하는 상품이나 서면 승낙을 줄 때.
