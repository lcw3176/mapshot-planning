# 배포 중단은 이미지를 먼저 받아 줄이고, 무중단은 DB 를 서버 밖으로 뺀 뒤에 본다

> 날짜: 2026-11-25 · 영향 레포: API / 운영

## 계기

배포할 때마다 서비스가 멈추는 시간이 길었다. Cloud Run 같은 관리형 서비스로 옮기는 안도 나왔다.

## 결정

- `deploy-prod` 순서를 `down --rmi all → up` 에서 `pull → up -d → image prune` 으로 바꿨다(Mapshot-API #139).
  서버가 도는 동안 이미지를 먼저 받고 컨테이너만 바꿔 끼워서, 멈추는 시간이 JVM 기동 시간(대략 10~20초, 추정)으로 줄어든다.
- 완전 무중단(새 컨테이너를 먼저 띄우고 옛 것을 내리기)은 H2 파일 DB 때문에 지금은 안 된다. H2 파일은 한 프로세스만 열 수 있다.
  무중단이나 관리형 서비스 이전은 DB 를 서버 밖으로 뺀 다음에 다시 본다.
- DB 후보는 Supabase 무료(Postgres, 서울 리전)로 본다. 웹 화면에서 데이터를 바로 볼 수 있다는 점도 이유다. 진행은 운영자 확인 후.

## 버린 선택지

- 지금 바로 Cloud Run 이전: 컨테이너 디스크가 임시라 H2 파일 DB 가 배포 때마다 사라진다. 요청이 없으면 인스턴스가 0개가 돼
  서버 안 스케줄러(매시 보도자료, 매일 브리핑)가 돌지 않고, 첫 요청마다 스프링 기동(10~20초)을 기다리게 된다.
- Cloud SQL: 무료 구간이 없다(인프라 비용 추가).
- 같은 VM 에 Postgres 컨테이너: 비용은 없지만 VM 메모리 여유와 데이터 확인 편의(SSH 터널)가 걸린다. Supabase 가 막히면 다시 본다.

## 이 결정을 다시 볼 조건

- DB 를 서버 밖으로 옮긴 뒤(무중단 배포·Cloud Run 재검토).
- 배포 중단이 여전히 문제가 될 때.
